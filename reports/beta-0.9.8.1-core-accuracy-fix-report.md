## 一、修复前失败的 2 个核心人格

### 失败项 #1：守门人型 (gatekeeper)

| 指标 | 数值 |
|------|------|
| 预期主岛 | 守门人型 |
| 实际 #1 | 岛屿型 (87分) |
| 守门人自身排名 | #2 (81分) |
| 分差 | 6 分 |
| 失败原因 | AU 和 ST 高阈值无法被黄金路径达到 |

**根因分析**：

黄金路径为每个场景选择最接近 targetVector 的选项。守门人型的 AU=82 和 ST=78：
- AU 82：选项离散值为 0/33/67/100。|67-82|=15 < |100-82|=18 → **选择 67**
- ST 78：|67-78|=11 < |100-78|=22 → **选择 67**

结果 AU 实际≈67，ST 实际≈67，双双低于自设阈值（AU≥78, ST≥68），触发 -12 的 failPenalty。

而岛屿型的 targetVector 与守门人非常接近（高 AU、高 ST、低 EX、低 NV），且岛屿的 AU 和 ST 阈值更低，不易被罚分。在 golden path 实际得分相似的情况下，岛屿型因更少罚分而胜出。

### 失败项 #2：候鸟型 (migratory_bird)

| 指标 | 数值 |
|------|------|
| 预期主岛 | 候鸟型 |
| 实际 #1 | 流浪诗人型 (87分) |
| 候鸟自身排名 | #3 (81分) |
| 分差 | 6 分 |
| 失败原因 | AU 和 NV 高阈值无法被黄金路径达到 |

**根因分析**：

候鸟型的 AU=82 和 NV=78：
- AU 82：|67-82|=15 < |100-82|=18 → **选择 67**，AU 实际≈67，低于阈值 72
- NV 78：|67-78|=11 < |100-78|=22 → **选择 67**，NV 实际≈67，低于阈值 68

候鸟型和流浪诗人型的向量相似（高 NV、高 AU、低 ST、高 EV）。在候鸟无法达到自身 AU/NV 阈值的情况下，流浪诗人型成为更好的匹配。

**离散选项的临界值规律**：
- 选项值为 0, 33, 67, 100
- target ≥ 83.5 时，黄金路径选择 100（|67-83.5|=16.5 > |100-83.5|=16.5，恰好相等）
- target < 83.5 时，黄金路径选择 67
- target ≥ 84 确保选择 100

## 四、维度路径失败项如何修复

### 失败项：CA 高路径得分=78 (期望≥85)

**根因**：审计脚本 `scripts/option-alignment-audit.mjs` 假设 `s.options[0]` 总是最高分选项（A=100）。但 CA 维度的 scene-27 "沉重的行囊" 的选项排序为：

| 选项 | 文本 | score |
|------|------|-------|
| A | 检查行囊，把属于别人的东西还给别人，属于自己的留着 | 33 |
| B | 放下一些最重的东西，但留几样最重要的 | 67 |
| C | 觉得每样东西都很重要，舍不得放下任何一件 | **100** |
| D | 把整个行囊放在路边——旅途不需要那么多负担 | 0 |

A=33, C=100 的排序与标准 A=100 排序不同。审计脚本取 `options[0]`（即 A=33）作为高路径选项，导致 CA 高路径得分 = (100+100+33)/3 = 78。

**修复**：将高路径逻辑从 `s.options[0]`（假设第一个是最高分）改为 `s.options.reduce((a,b) => a.score >= b.score ? a : b)`（查找实际最高分选项），低路径同理改为查找实际最低分选项。

所有其他维度的 options[0] 恰好都是最高分选项，因此此项修复仅影响 CA 维度的审计结果。

## 十、技术总结

### 问题本质

选项离散化导致了"临界值陷阱"：targetVector 中的值如果在 67 和 100 的中间点 (83.5) 以下，黄金路径会选择 67 而非 100。当该维度的 coreThreshold 要求 ≥某个值，而 67 达不到该阈值时，类型会被自己的黄金路径"罚掉"。

### 修复策略

将受影响的 targetVector 值从 82/78 提升到 84，跨越离散化临界点 (83.5)，使黄金路径选择 100 而非 67。这是最小化、最精准的修复——只改 4 个数值，不改算法、不改阈值、不改题目。

### 为什么不改阈值

降低 coreThreshold（如 AU:78→65）也能让 67 通过，但会：
1. 弱化类型区分度
2. 影响真实用户匹配
3. 让不达标的用户也被匹配到守门人型

提高 targetVector 是更优方案——它既让黄金路径通过，又不会弱化类型的核心特质要求。
