# 心岛 v2.0 主性人格命名系统重构方案

## 1. 总结结论

本轮建议对 v2.0 的 15 个主性人格进行一次整体命名系统重构。原因不是现有全部名字都不可用，而是当前候选名单同时混合了角色名、自然意象名、功能模块名和旧版本惯性命名，放在同一套产品中会削弱品牌统一性和传播记忆点。

最推荐路线是：以“心岛自然意象系”为主命名系统，结果页主展示继续使用“XX型”，同时在视觉叙事和分享卡中使用“你的心岛：XX岛”的双层表达。这样既保留人格测试的清晰识别，又强化心岛产品的世界观与分享感。

本轮只输出命名策略，不修改代码、不修改题库、不修改评分、不修改人格文案、不改资源。

## 2. 是否改动代码

没有。

本轮未修改 `app.js`、题库、评分配置、样式、图片资源、部署目录或任何运行文件。只新增本报告。

## 4. 命名原则

人格名是品牌资产，不是构念翻译。它需要让用户愿意认领、截图、转发和讨论，而不是让用户看到量表维度。

v2.0 命名应遵守以下原则：

| 原则 | 说明 |
| --- | --- |
| 统一意象系统 | 同一批人格名应像来自同一个世界，而不是来自不同产品模块 |
| 避免功能直译 | 避免“合拍规划、情绪修复、现实匹配、高边界”等量表词 |
| 关系识别准确 | 名字不能只好听，也要能映射恋爱中的关系模式 |
| 可被用户认领 | 用户看到结果后应能说“这就是我”，而不是“这是一个维度结论” |
| 适合分享卡 | 名字需要短、清楚、有画面，适合放在结果页和小红书标题 |
| 不过度玄学 | 可以有星、月、潮等意象，但不能变成塔罗、占卜或神谕系统 |
| 不偏 RPG | 避免探险家、骑士、守卫者、召唤师、祭司等角色职业化命名 |
| 支持资产延展 | 名字应能自然延展成图标、拟人图、结果标题、岛屿名和视觉符号 |

## 7. 是否保留“型”

建议保留“型”，但不要让“型”承担全部品牌表达。

| 方案 | 表达 | 优点 | 风险 | 建议 |
| --- | --- | --- | --- | --- |
| A | XX型 | 用户一眼知道是人格测试结果 | 较普通，容易像传统心理测试 | 作为主结果标签保留 |
| B | XX岛 | 最贴合心岛世界观，适合分享 | 人格属性不够明确 | 作为视觉叙事与分享副标题 |
| C | 主性人格：XX型 / 你的心岛：XX岛 | 兼顾人格识别与品牌氛围 | 需要一套映射表 | 最推荐 |

推荐结果页结构示例：

| 层级 | 示例 |
| --- | --- |
| 主标题 | 你的主性人格：回潮型 |
| 副标题 | 你的心岛：回潮岛 |
| 命中句 | 你不是不会受伤，而是总能让关系重新回到可说话的地方 |

## 10. 下一步建议

1. 先确认 v2.0 是否采用“XX型 + XX岛”的双层命名结构。
2. 再确认最终 15 个推荐名是否全量采用，或只在少数名字上替换。
3. 命名定稿后，再进入 v2.0 结果文案重写，不要先改代码。
4. 结果文案定稿后，建立 `personaId -> displayName -> islandName -> legacyName` 的映射表。
5. 视觉资产最后处理，优先检查旧拟人图是否还能承接新名字。
6. 在 v2.0 工程实现前，继续保持当前 Beta 0.9.9.7 / 0.9.9.x 线上版本稳定，不把未定稿命名混入现有生产入口。
