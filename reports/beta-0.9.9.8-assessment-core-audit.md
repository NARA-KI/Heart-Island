# 心岛计划 Beta 0.9.9.8 测评内核审计报告

## 1. 总结结论

本轮只做测评内核审计，没有修改题库、人格文案、评分算法、评分参数、targetVector、UI 或部署文件。审计对象为当前运行基线 `Beta 0.9.9.7` 的测评结构，结合 `app.js`、`core/scoring.mjs`、`core/calibration-profiles.mjs`、`scripts` 与已有审计产物 `reports/probability-audit-calibrationB.json`、`reports/option-result-alignment-audit.json`。

核心结论：

| 判断项 | 结论 | 风险等级 | 说明 |
| --- | --- | --- | --- |
| 是否建议整体重写题库 | 不建议 | 低 | 36 题结构完整，12 维度各 3 题，选项分值完整；问题主要是少数题目的区分度和抽象度。 |
| 评分机制是否高风险 | 不是高风险，但有中风险 | 中 | 12 核心人格自匹配 12/12 通过；但 Top1/Top2 gap≤5 的模拟比例为 65.0%，说明近邻人格很多。 |
| 12 核心人格是否清晰 | 基本清晰 | 中 | 大多数人格有明确锚点；月光/镜像、候鸟/流浪诗人、守门人/观星者等边界需要用户验证。 |
| 是否现在改评分参数 | 不建议 | 中 | 当前 `calibrationB` 可用，先收集真实用户准确度、近邻人格与 Top1-Top2 gap，再决定是否调参。 |
| 是否需要 DeepSeek 介入结果文案 | 需要，但不应现在整体重写 | 中 | 建议在真实用户反馈后做定向改写，重点强化易混人格的“一句话差异”。 |
| 是否先做真实用户验证 | 建议优先 | 高优先级行动 | 当前最缺的是 10-30 人真实反馈，不是继续凭内部感觉改题库或调分。 |

整体判断：当前测评内核具备继续公开小样本测试的基础，不应在没有真实用户反馈前大规模重写。下一步应以“真实用户验证 -> 定位混淆人格和低命中题 -> 小范围修题/修文案 -> 再跑审计”的顺序推进。

## 4. 36 题题目与选项质量审计

### 4.1 总体判断

36 题没有缺题、重复题或编号错乱；每题均有 4 个选项与分值。大多数题目采用 100 / 67 / 33 / 0 的单维递减结构，便于用户理解，也便于审计。当前题库的问题不是结构损坏，而是以下三类产品风险：

| 风险类型 | 说明 | 影响 |
| --- | --- | --- |
| 文学化偏高 | 海螺、星星、湖水、旧船等隐喻贯穿全题 | 氛围强，但部分用户可能觉得“不是恋爱选择题”。 |
| 社会赞许偏差 | 修复、照顾、承诺类题目中，高分选项容易看起来更善良 | 用户可能选“更好的人”，而不是更像自己。 |
| 维度重叠 | 修复与照顾、自由与新鲜、情绪敏感与灵魂理想存在交叠 | 会增加近邻人格混淆。 |

| 3 | scene-05 盘旋的鹰 | AU 自由边界中“自由”和“孤单”绑定，可能让真实高边界用户回避高分。 |
| 4 | scene-08 灯塔的信号 | SE 安全确认与 AU/NV 探索节奏混在一起，B 选项含义不够单纯。 |
| 5 | scene-35 湖中的倒影 | EV 情绪敏感与 EX 表达/自我认同混合，且抽象度偏高。 |

## 5. 评分机制合理性审计

### 5.1 当前评分入口与流程

当前主流程：

1. 用户每题选择一个选项，记录 `dimension` 与 `score`。
2. 36 题完成后，按 12 个维度聚合平均分，未答维度默认 50。
3. `matchAllTypes(avgDimensionScores, 'core')` 在 12 核心人格池中匹配。
4. 每个人格按 `targetVector` 计算用户维度分与人格目标向量的加权差异。
5. 命中 `coreThresholds` 的关键维度给 `metBonus`，未命中给 `failPenalty`。
6. 排序后产生主结果、次结果与 Top5；debug/audit 可调用 `matchAllTypesDebug` 查看 20 类型。

### 5.2 生产口径

| 项目 | 当前状态 |

| 生产 profile | `calibrationB` |
| 参数 | `coreWeight=2.20`、`metBonus=2.0`、`failPenalty=6.0` |
| 前台结果池 | 12 核心人格 |
| debug/audit 池 | 可查看全 20 类型 |
| 一键检查 | `npm run check`、`npm test` |

### 5.4 评分风险判断

| 检查项 | 当前状态 | 风险 | 建议 |
| --- | --- | --- | --- |
| 维度平均分 | 每维 3 题平均 | 中 | 对 H5 足够，对严肃测评不够；避免专业诊断表述。 |
| targetVector 匹配 | 12 维向量距离匹配 | 低 | 结构自洽，保留。 |
| coreWeight | 核心阈值维度权重 2.20 | 低 | 不建议现在改。 |
| metBonus | 命中核心阈值 +2 | 低 | 不建议现在改。 |
| failPenalty | 未命中核心阈值 -6 | 低 | 不建议现在改。 |
| Top1/Top2 gap | gap≤5 比例高 | 中 | 反馈表应记录 gap 与第二人格。 |

| 全 20 池残留 | debug/audit 保留 | 中 | 继续保持命名清晰，避免前台误用。 |
| 旧分支 golden path | 旧船长、温室、黑森林不稳 | 低到中 | 旧分支不作为主结果，暂不处理。 |

结论：评分机制不是高风险；当前最大风险是“很多用户可能处于两个相近人格之间”，这更像 H5 人格测试的解释策略问题，而不是立即改参数的问题。建议在反馈中记录 Top1、Top2、gap、用户自评准确度，再决定是否调题或调参。

### 7.2 是否需要 DeepSeek 介入

建议需要 DeepSeek 介入，但不是现在整体重写。更合理的介入方式：

1. 先做 10-30 人真实用户验证。
2. 找出准确度低、用户觉得“不像我”的人格。
3. 针对易混对写“一句话边界”和“关系建议”。
4. 不重写当前已能传播的命中句，除非用户反馈集中指向问题。

## 9. 真实用户验证方案

### 9.1 样本建议

| 阶段 | 样本 | 目的 |
| --- | --- | --- |
| 第一轮 | 10-30 人 | 判断结果准不准、题目好不好选、分享卡是否愿意保存 |

### 9.3 决策标准

| 反馈结果 | 处理方式 |
| --- | --- |
| 某题被多人标记“不好选” | 优先修题，不先改评分。 |

| 镜像型真实样本显著偏高 | 检查 EV/CA/SE 是否过度容易拿高分。 |
