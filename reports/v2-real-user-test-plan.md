# 心岛 v2 双模式真实用户最小可行内测方案

## 版本信息

- 目标版本：v2 trusted-beta（production）
- 测试范围：60 题双模式（quick 30 + full 60 + direct full 60）
- 当前部署：CloudBase 静态托管 + CloudBase AI Report 云函数
- 方案日期：2026-07-09

---

## 1. 第一轮建议测试人数

**12–20 人。**

拆解：

| 层次 | 人数 | 说明 |
|------|------|------|
| 核心亲友 | 8–10 人 | 可深度追问，能容忍中途问题 |
| 弱关系/社交媒体招募 | 4–6 人 | 更接近真实用户行为，减少"礼貌偏差" |
| 最少有效样本 | 12 人 | 低于此数无法判断是题目问题还是个体差异 |

不建议超过 20 人——第一轮目标是**发现问题**，不是统计显著性。

---

## 2. 测试对象基本筛选条件

**必须满足：**

1. 18 岁以上
2. 至少有过一段 3 个月以上的恋爱关系 / 深度暧昧经历
3. 能阅读中文
4. 使用自己的手机（不做设备统一）

**建议分层：**

| 维度 | 目标分布 |
|------|----------|
| 性别 | 尽量接近 1:1 |
| 年龄 | 覆盖 20–35 岁为主，允许 1–2 人 35+ |
| 恋爱状态 | 至少 3 人正在关系中，至少 3 人单身 |
| 对心理测试的态度 | 不要全是"心理学爱好者" |

**排除条件：**

- 参与过 v2 题目设计或内测讨论的人
- 已知道自己的"心岛人格类型"的人（如之前做过旧版）
- 职业心理测量/心理咨询从业者（他们的反馈是专家意见，不是用户意见）

## 3. 用户测试完整流程

### 3.1 发送前准备

- [ ] 准备一份简短邀请语（见 3.2）
- [ ] 确认生产 URL 可访问（https://xindao-mvp06-d9gf6ion1b76a1327-1442533234.tcloudbaseapp.com/）
- [ ] 确认 AI Report 云函数正常
- [ ] 准备反馈表单（飞书/腾讯问卷/Google Forms）

### 3.2 邀请语模板

> 我在做一个恋爱关系倾向的小测试（心岛计划），目前是第一轮真实用户试用。想请你帮忙做一下，然后给我一些真实反馈。
>
> 测试大约需要：
> - 快速版：4–6 分钟（30 题）
> - 如果你愿意继续做完深度版：再加 4–6 分钟（总共 60 题）
>
> 完全匿名，不会记录你的个人信息。做完有一份 AI 生成的人格分析报告。
>
> 链接：[URL]
>
> 几点小请求：
> 1. 请用手机打开，像平时刷手机一样自然做
> 2. 不要过度思考，选最接近自己真实反应的选项
> 3. 做完后填一下这个简短反馈：[反馈表单链接]
> 4. 如果中途有任何卡住/困惑/不想做了，也请告诉我

### 3.3 用户实际操作流程

```
收到链接
  → 打开页面（home 双模式选择）
  → 选择"快速探索"或"深度探索"
  → 阅读说明页
  → 开始做题（30 或 60 题）
  → [如果是 quick] 看到 AI 报告 → 可选择继续答完剩余 30 题
  → [如果是 quick→full 续答] 答完 30→60 题 → 看到完整 AI 报告
  → 看到完整 AI 报告结果
  → 填写反馈表单
```

测试者可以自由选择 quick 或 full 入口。不强制要求每个人都做完 60 题——**这正是要观察的行为数据**。

### 3.4 测试者指导

- **不要**在旁边看着他们做（会造成压力）
- **不要**解释题目含义（如果需要解释，说明题目有问题）
- **可以**在完成后追问："有没有哪道题让你犹豫了很久？""有没有觉得某道题怎么选都不对？"
- **如果对方中途放弃**：记录下来，追问为什么

## 4. 测试后反馈问题

### 核心问题（必答）

| # | 问题 | 类型 |
|---|------|------|
| 1 | 你觉得测试结果像你吗？（1–5） | 量表 |
| 2 | 你觉得 AI 分析报告说得准吗？（1–5） | 量表 |
| 3 | 结果中哪部分最像你？ | 自由文本 |
| 4 | 结果中哪部分最不像你？ | 自由文本 |
| 5 | 做题过程中有没有哪道题让你不知道怎么选？如果有，是什么情况？ | 自由文本 |
| 6 | 你有没有觉得有些选项看起来都差不多？ | 是/否 |
| 7 | 你有没有觉得有些选项明显"更对"或"更成熟"，让你不好意思不选？ | 是/否 |
| 8 | 如果这个测试要分享给朋友，你愿意吗？ | 是/否 |

### 可选追问（对愿意深入聊的人）

- 做 30 题后看到报告，什么让你决定继续 / 不继续做完 60 题？
- 有没有哪道题的措辞让你觉得"这话不像我会说的"？
- 整体感觉像做了一个心理测评，还是像在回答朋友的问题？
- 你觉得题目数量合适吗？

## 5. 数据指标定义

### 5.1 流程漏斗指标

| 指标 | 定义 | 数据来源 |
|------|------|----------|
| **home_view** | 到达首页的人数 | 埋点/页面 PV |
| **quiz_mode_selected** | 点击 quick 或 full 的人数 | 埋点 |
| **quiz_started** | 从说明页点击"开始"的人数 | 埋点 |
| **quick_started** | 选择 quick 模式的人数 | quiz_mode_selected 分解 |
| **full_started** | 选择 full 模式（含 direct full）的人数 | quiz_mode_selected 分解 |
| **quick_completed** | 答完 30 题并看到过渡页的人数 | 埋点 |
| **quick_report_viewed** | quick 模式看到 AI 报告的人数 | 埋点 |
| **continue_full_clicked** | 在 quick 报告页点击"继续深度探索"的人数 | 埋点 |
| **full_completed** | 答完 60 题并看到过渡页的人数（含 direct + continuation） | 埋点 |
| **full_report_viewed** | 看到 60 题完整 AI 报告的人数 | 埋点 |
| **ai_report_success** | AI 报告成功展示的次数（quick + full 分别统计） | 埋点 |
| **ai_report_failed** | AI 报告失败/降级为 deterministic 的次数 | 埋点 |
| **feedback_submitted** | 提交反馈表单的人数 | 反馈表单 |

### 5.2 衍生指标

| 指标 | 计算方式 |
|------|----------|
| **30 题开始率** | quick_started / home_view |
| **30 题完成率** | quick_completed / quick_started |
| **30 题平均耗时** | 计时器差值（开始→过渡页） |
| **30→60 续答点击率** | continue_full_clicked / quick_report_viewed |
| **60 题最终完成率** | full_completed / (continue_full_clicked + full_started_direct) |
| **AI 报告成功率** | ai_report_success / (ai_report_success + ai_report_failed) |
| **人格命中感** | 反馈问题 1 的平均分（1–5） |
| **AI 报告满意度** | 反馈问题 2 的平均分（1–5） |
| **分享意愿** | 反馈问题 8 的"是"比例 |

### 5.3 定性信号

- 自由文本中提到的"最不像自己"的人格描述是否集中在特定类型
- 放弃做题的位置（第几题附近）
- "不知道怎么选"的题目是否集中

## 6. 判断版本是否需要继续修改的阈值

| 指标 | 绿灯（继续） | 黄灯（关注） | 红灯（必须修） |
|------|-------------|-------------|---------------|
| 30 题完成率 | ≥ 85% | 70–84% | < 70% |
| 30→60 续答率 | ≥ 40% | 25–39% | < 25% |
| 人格命中感（均值） | ≥ 3.5 | 2.5–3.4 | < 2.5 |
| AI 报告满意度（均值） | ≥ 3.5 | 2.5–3.4 | < 2.5 |
| AI 报告成功率 | ≥ 90% | 80–89% | < 80% |
| "有明显诱导选项"反馈比例 | ≤ 20% | 21–40% | > 40% |
| "选项差不多"反馈比例 | ≤ 30% | 31–50% | > 50% |

**决策规则：**

- 全部绿灯 → 版本冻结，进入第二轮（30–50 人扩大测试）
- 1–2 个黄灯 → 针对性修复后重测 5–8 人
- 任意红灯 → 不能扩大测试，必须先修复根本问题

## 7. 数据记录方案

### 7.1 埋点实现（最小可行）

不需要引入任何分析平台。利用现有的 `window.__heartIslandV2Debug` 调试接口，在关键节点 push 事件到数组：

```js
// 最小埋点：挂到已有的 debug state 上
if (!window.__heartIslandV2Debug._beacons) {
  window.__heartIslandV2Debug._beacons = [];
}
window.__heartIslandV2Debug._beacons.push({
  event: 'quick_completed',
  ts: Date.now(),
  questionCount: 30,
});
```

**需埋点位置（均已存在于当前 DOM 中）：**

| 事件 | 触发时机 | 现有 hook |
|------|----------|-----------|
| `home_view` | 首页 `[data-action="start"]` 可见 | `openFresh()` 完成 |
| `quiz_mode_selected` | 点击 `[data-quiz-mode="quick"]` 或 `[data-quiz-mode="full"]` | 已有 data 属性 |
| `quiz_started` | 说明页点击 `[data-action="begin"]` | 已有 data 属性 |
| `quick_completed` | `.v2-transition--quick` 出现 | 已有 CSS class |
| `quick_report_viewed` | `[data-ai-report-panel][data-ai-state="success"]` 可见 | 已有 data 属性 |
| `continue_full_clicked` | 点击 `[data-action="continue-full"]` | 已有 data 属性 |
| `full_completed` | `.v2-transition--full` 出现 | 已有 CSS class |
| `full_report_viewed` | 同上 quick_report_viewed | 已有 data 属性 |
| `ai_report_success` | AI report panel state=success | 已有 data-ai-state |
| `ai_report_failed` | AI report panel state=error | 已有 data-ai-state |
| `feedback_submitted` | 点击反馈按钮 | 已有 `recordFeedbackClick()` |

**推荐实现方式：** 在 `js/v2/app.js` 或独立 `js/v2/beacons.js` 中添加不超过 40 行的 beacon dispatch 函数，监听 DOM 变化或利用现有状态机的 state transition。

### 7.2 用户反馈收集

使用飞书表单或腾讯问卷（不需要自己开发）：

| 字段 | 类型 | 是否必填 |

| 人格命中感 (1–5) | 量表 | 是 |
| AI 报告满意度 (1–5) | 量表 | 是 |

| 最不像你的部分 | 自由文本 | 否 |
| 有无困惑的题目 | 自由文本 | 否 |
| 选项是否太相似 | 是/否 | 是 |
| 是否有"标准答案"感 | 是/否 | 是 |
| 是否愿意分享 | 是/否 | 是 |
| 任何想说的 | 自由文本 | 否 |

### 7.3 测试者追踪

## 8. 隐私和数据最小化原则

### 8.1 不收集的数据

| 数据类别 | 是否收集 | 说明 |
|----------|----------|------|
| 每题具体答案 | **否** | 禁止上传到任何服务器 |
| 姓名/手机号/邮箱 | **否** | 完全匿名 |
| IP 地址精确信息 | **否** | 不主动记录 |
| GPS 位置 | **否** | 不请求 |
| 社交账号 | **否** | 不要求登录 |
| 设备指纹 | **否** | 不采集 |

### 8.2 可以收集的数据

| 数据类别 | 用途 | 存储位置 |
|----------|------|----------|
| 匿名结果 ID | 追踪完成率 | 埋点数组（浏览器内存） + 反馈表单 prefilled |
| 人格类型 | 统计分布 | 反馈表单 prefilled |
| 模式选择（quick/full） | 漏斗分析 | 埋点数组 |
| AI 报告成功/失败 | 稳定性监控 | 埋点数组 |
| 用户自由文本反馈 | 定性分析 | 反馈表单 |
| 浏览器视口宽度 | 移动端适配 | 反馈表单 prefilled（已有） |

### 8.3 数据流向

```
用户浏览器（埋点数组，不发送）
  → 用户主动提交反馈表单（仅包含人格类型 + 自由文本 + 匿名 ID）
    → 飞书/腾讯问卷（第三方，数据归测试者所有）
```

### 8.4 知情同意

邀请语中已说明：
- 完全匿名
- 不会记录个人信息
- 做完有一份 AI 分析报告

反馈表单第一行增加：
> 你的反馈仅用于改进这个测试的设计。数据不会公开，不会关联到你的个人身份。

### 8.5 暂停/删除

- 若收集到 ≥ 12 份（或 ≥ 20 份）有效反馈，停止招募
- 反馈表单设置自动关闭日期（建议 14 天后）
- 分析完成后，导出数据并删除表单中的原始回复

## 9. 禁止事项（再次确认）

- ❌ 上传每题具体答案
- ❌ 上传用户自由文本以外的敏感信息
- ❌ 引入 Google Analytics、百度统计、Sentry 等大型分析平台
- ❌ 为了埋点重构应用架构
- ❌ 修改评分和人格逻辑
- ❌ 将 AI 模拟结果冒充真实用户数据
- ❌ 在 CloudBase 函数中记录用户数据
- ❌ 在 deploy 目录中添加任何数据收集代码
