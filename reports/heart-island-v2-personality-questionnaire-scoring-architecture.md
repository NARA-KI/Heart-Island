# 心岛 v2.0 主性人格矩阵与题库评分系统重构方案

## 1. 总结结论

本轮只输出方案文档，没有修改代码、题库文件、评分文件、UI 或部署文件。

核心结论：

| 议题 | 建议 |
| --- | --- |
| 底层构念 | 采用 15 构念。上一轮提出的“关系投入与记忆”应拆为“关系投入 / 留下倾向”和“回忆牵引 / 关系叙事”。 |
| 题量 | 采用 60 题，即 15 构念 x 每构念 4 题。 |
| 题目结构 | 每构念 4 题：核心倾向、真实关系场景、压力/冲突场景、反向/边界题。 |
| 选项结构 | 移动端保持 4 选项，内部使用 0 / 33 / 67 / 100 或反向映射。 |
| 计分原则 | 每题原则上只影响一个主构念；首版不建议一题多构念加权。 |
| 人格数量 | 推荐 15 个候选主性人格，后续可收敛到 12-15 个正式人格。 |
| 旧 12 人格 | 大部分可保留为候选，但必须重建构念锚点；不为保旧人格扭曲题库。 |
| 新增人格 | 建议新增现实匹配、关系信任、情绪修复/调节方向的人格候选。 |
| 用户端展示 | 只展示一个主性人格；Top2、构念高低、冲突组合只进入白话解析。 |
| 是否现在写 60 题 | 不建议。先定构念、人格矩阵、评分规则，再生成题库候选。 |
| 是否现在改代码 | 不建议。代码实现应在题库与评分架构定稿之后。 |

v2.0 的核心不是“把旧题库扩成 60 题”，而是建立一个可追溯闭环：

```text
题目 -> 选项分值 -> 构念分 -> 人格向量匹配 -> 主性人格 -> 白话解析素材 -> 结果页
```

每一道题、每一个选项、每一段结果文案，都必须能追溯到构念或人格，不允许只凭氛围写题、写人格或写结果。

## 3. v2.0 新核心原则

### 3.1 准确性第一

题量、流程、UI、故事线都要服从测评准确性。不要为了压缩题量，把多个构念塞进同一道题或同一个选项。

### 3.2 题库与评分强绑定

题库不能只是“好看的问题”。每题必须标注：

| 字段 | 用途 |
| --- | --- |
| 对应构念 | 明确这题测什么。 |
| 题型功能 | 核心倾向、真实关系、压力冲突、反向边界。 |
| 评分方向 | 高分代表什么，低分代表什么。 |
| 选项分值 | 每个选项对应真实分值。 |
| 是否反向计分 | 防止用户惯性选择高分选项。 |
| 是否用于人格区分 | 标明它会影响哪些人格边界。 |
| 是否用于结果解析 | 标明该题是否可沉淀为白话解析素材。 |

### 3.3 人格是输出层，不是底层理论

主性人格应由 15 构念组合自然生成。旧人格可以保留、改名、合并或删除，但不应反向绑架题库。

### 3.4 内部复杂，外部简单

内部可以计算：

| 内部计算 | 用户端是否展示 |
| --- | --- |
| 15 构念分 | 不展示 |
| 主人格匹配分 | 不展示为复杂分表 |
| 第二匹配人格 | 不展示为 Top2 / 副人格 |
| 高低构念 | 转成白话解析 |
| 构念冲突 | 转成白话解析 |
| 近邻人格差异 | 用于文案判别，不作为标签展示 |

用户端只展示：

1. 一个主性人格。
2. 一句命中句。
3. 3 个关键词。
4. 白话情感解析。
5. 关系卡点。
6. 相处建议。
7. 分享卡。

## 7. 题目与评分绑定规则

### 7.1 是否继续使用 100 / 67 / 33 / 0

建议继续使用 4 档分值，但内部标准写成 `0 / 33 / 67 / 100`。原因：

| 方案 | 判断 |
| --- | --- |
| 4 选项，0/33/67/100 | 推荐。移动端压力小，足够表达倾向强弱。 |
| 5 选项，0/25/50/75/100 | 暂不推荐。移动端更累，用户容易选中间项。 |
| 7 点量表 | 不推荐。不符合心岛 H5 的沉浸体验。 |

### 7.2 反向题计分

反向题不是“低分题”，而是构念方向相反的验证题。

示例：

| 题目目的 | 用户选择 | 构念分 |
| --- | --- | --- |
| 测自主边界 | 选择“我需要先保留自己的时间” | 高分 |
| 反向测自主边界 | 选择“我愿意让对方进入所有日常” | 低分 |

反向题必须在题库文件中明确标注：

| 字段 | 示例 |
| --- | --- |
| `isReverse` | `true` |
| `construct` | `AU` |
| `scoreMap` | A:0 / B:33 / C:67 / D:100 |

### 7.3 如何避免 A 永远高分、D 永远低分

| 方法 | 说明 |
| --- | --- |
| 选项顺序不固定 | 同一题的高分选项不固定在 A。 |
| 用户端随机选项顺序 | 展示顺序可随机，但评分文件记录真实分值。 |
| 题型交错 | 反向题和压力题穿插，避免用户猜模式。 |
| 选项策略均合理 | 不写“成熟沟通 vs 逃避问题”这种明显好坏。 |

### 7.4 是否允许一题影响多个构念

首版不建议。一题原则上只影响一个主构念。

允许记录辅助标签，但不参与分数：

| 字段 | 用途 |
| --- | --- |
| 主构念分 | 用于正式计分。 |
| 辅助标签 | 用于结果文案素材，例如“更容易等待对方先开口”。 |
| 不参与人格匹配 | 避免构念混杂。 |

## 12. 评分系统设计

| 阶段 | 输入 | 处理 | 输出 | 风险 | 建议 |
| --- | --- | --- | --- | --- | --- |
| Step 1：题目得分 | 用户选择的选项 | 读取该选项真实分值 | 单题构念分 | 选项顺序随机后取错分 | 评分文件必须以 optionId 绑定真实分值。 |
| Step 2：构念聚合 | 每构念 4 题分数 | 计算平均分、离散度、反向题一致性 | 15 构念分 | 某构念内部不一致 | 记录构念置信度。 |
| Step 3：人格匹配 | 用户 15 构念分、人格 targetVector | 加权距离 + 核心构念权重 + 排斥构念扣分 | 主人格排序 | 近邻人格过多 | 保留 gap，但用户端不展示 Top2。 |
| Step 4：内部倾向识别 | Top1、Top2、高低构念、冲突组合 | 提取解析素材 | 白话解释素材 | 解释过度复杂 | 限制用户端只输出 3-5 个重点。 |
| Step 5：白话情感解析 | 主人格 + 解析素材 | 套用文案规则和人格语气 | 结果页内容 | 术语外露 | 禁止展示构念术语和复杂分表。 |

推荐人格匹配规则：

1. 基础分：计算用户 15 构念与 targetVector 的加权平均距离。
2. 核心构念加权：人格的 3-4 个核心构念权重更高。
3. 排斥构念扣分：如果用户在该人格排斥构念上过高或过低，扣分。
4. gap 记录：记录 Top1 与 Top2 差距，用于内部判断解析语气。
5. 置信度参与语气，不参与用户端标签。

## 13. 构念置信度与题目一致性

| 情况 | 判断 | 处理方式 |
| --- | --- | --- |
| 4 题分数高度一致 | 构念置信度高 | 可用于强解析。 |
| 4 题分数中等分散 | 构念置信度中 | 解析时使用“你可能”“你有时”。 |
| 核心题和反向题冲突 | 构念置信度低 | 不作为强标签，只作为辅助素材。 |
| 多个人格分数接近 | 主结果仍展示 Top1，但解析更柔和 | 不展示 Top2，用“你身上也有另一种倾向”式白话。 |
| 某构念 4 题全部极端 | 可能是强倾向，也可能是作答模式 | 结合反向题一致性判断。 |
| 多个构念都低置信 | 结果页避免绝对判断 | 加强“倾向”措辞。 |

用户端不展示“置信度”这个词。内部只用它来避免结果说得太绝对。

## 15. 题库与结果解析闭环

v2.0 必须建立以下追溯规则：

| 资产 | 必须能追溯到 |
| --- | --- |
| 每一道题 | 一个主构念。 |
| 每一个选项 | 一个明确分值和评分方向。 |
| 每个构念 | 至少影响人格匹配或结果解析。 |
| 每个人格 | 至少 3 个核心高分构念和 1-2 个低分/边界构念。 |
| 每段结果文案 | 主人格、构念高低或构念组合。 |
| 每张分享卡短句 | 主人格核心命中句。 |

禁止：

1. 凭氛围写题。
2. 凭氛围写人格。
3. 凭氛围写结果文案。
4. 为了故事线牺牲题目清晰度。
5. 为了保留旧人格扭曲构念。

## 16. 轻叙事与评分的关系

轻叙事只影响题干包装，不影响评分逻辑。

| 题目写法类型 | 是否推荐 | 原因 |
| --- | --- | --- |
| 纯心理问卷式 | 不推荐作为主风格 | 准确但失去心岛产品差异化。 |
| 纯诗意隐喻式 | 不推荐 | 氛围强但测不准，用户难代入真实关系。 |
| 轻叙事 + 真实关系场景 | 推荐 | 保留心岛氛围，同时测真实行为。 |
| 强剧情任务式 | 不推荐 | 容易变成 RPG 选择，不像恋爱人格测试。 |
| 现实场景 + 心岛轻隐喻 | 推荐 | 最适合 v2.0：关系行为清楚，氛围不过载。 |

原则：

1. 故事情境不能改变题目构念。
2. 如果故事包装让题目测不准，优先保留测评准确性。
3. 心岛风格应体现在章节、场景、语气，而不是牺牲问题清晰度。

## 17. 后续执行路线
