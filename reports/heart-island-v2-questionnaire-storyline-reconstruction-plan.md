# 心岛 v2.0 题库与故事线重构方案

## 1. 总结结论

本轮只输出方案文档，没有修改代码、题库、评分、人格、UI 或部署文件。

核心判断：

| 议题 | 结论 |
| --- | --- |
| v2.0 底层方向 | 建议从旧版 12 维/12 人格，升级为“亲密关系构念框架 + 单主型人格输出”。 |
| 五层结构 | 建议保留，五层能覆盖亲密关系测试的主要过程。 |
| 十四构念 | 不建议机械锁死。14 构念基本可用，但“关系投入与记忆”过宽，建议拆成 15 构念；如果坚持 14 构念，则该构念至少增加题量。 |
| 推荐题量 | 准确性优先建议 60 题；若先做 v2.0 MVP，可用 56 题作为 14 构念标准版。 |
| 旧 12 维 | 需要大改。旧维度可作为素材，不应作为不可动标准。 |
| 旧 12 人格 | 需要大改。人格是输出层，应服务新构念，不应反向绑架题库。 |
| 故事线 | 建议轻叙事，不建议完整强剧情。故事线是氛围外壳，题目必须测真实关系行为。 |
| 结果展示 | 用户端只展示一个主性人格；第二倾向、高低构念、冲突组合只作为内部解释素材。 |
| 是否现在写 56 题 | 不建议立刻写完整题库；应先定稿构念、题量、题型模板和人格矩阵。 |
| 是否现在改代码 | 不建议。代码实现应在框架、题库、人格和评分规则稳定之后进入。 |

v2.0 的重点不是把 36 题加长，而是重建“测什么、怎么测、如何输出”的顺序。建议执行顺序为：框架定稿 -> 题库候选 -> 题库审计 -> 人格矩阵 -> 评分系统 -> 结果文案 -> 代码实现。

## 2. v2.0 新锚点

建议将 v2.0 产品锚点定义为：

> 心岛 v2.0 是一套基于五层亲密关系构念的恋爱人格测试。它参考亲密关系心理学框架，以依恋安全、爱情成分、爱情风格、关系运转和关系维持为底层结构，通过更准确的单构念题库，帮助用户理解自己在亲密关系中的安全感、边界、信任、亲密、激情、承诺、理想、探索、现实匹配、照顾支持、表达沟通、冲突修复、情绪调节和关系投入方式，并最终生成一个主性人格和一份白话化的个人情感解析。

使用边界：

| 可以说 | 不建议说 |
| --- | --- |
| 参考亲密关系心理学框架 | 科学诊断你的恋爱人格 |
| 帮助理解亲密关系中的模式 | 判断你有没有心理问题 |
| 娱乐向、探索向、反思向恋爱人格测试 | 专业临床量表 |
| 给出关系中的倾向、卡点和相处建议 | 给出绝对人格定论 |

## 3. 五层十四构念是否需要调整

### 3.1 五层结构判断

五层结构建议保留：

| 层级 | 覆盖范围 | 是否合理 | 说明 |
| --- | --- | --- | --- |
| 第一层：依恋与安全系统 | 安全确认、自主边界、关系信任 | 合理 | 对应关系开始和靠近时最核心的不安、距离、信任。 |
| 第二层：爱情成分系统 | 亲密连接、激情启动、承诺经营 | 合理 | 接近 Sternberg 爱情三角的亲密、激情、承诺，但表达更白话。 |
| 第三层：爱情风格系统 | 灵魂理想、新鲜探索、现实匹配、照顾支持 | 合理 | 覆盖被什么打动、如何表达爱、如何选择关系。 |
| 第四层：关系运转系统 | 表达沟通、冲突修复、情绪调节 | 合理 | 对应关系中的日常运行、压力、误会与修复。 |
| 第五层：关系维持与叙事系统 | 关系投入与记忆 | 当前偏薄 | 第五层目前只放一个构念，承担内容过宽，建议调整。 |

### 3.2 十四构念总评

| 构念 | 当前判断 | 是否过宽 | 是否重叠 | 建议 |
| --- | --- | --- | --- | --- |
| 安全确认 | 清晰 | 否 | 与关系信任有轻微重叠 | 保留。 |
| 自主边界 | 清晰 | 否 | 与新鲜探索、岛屿类人格相关 | 保留，避免写成逃避。 |
| 关系信任 | 必要新增 | 否 | 与安全确认相关但不同 | 新增，专测“能否承受暂时不确定”。 |
| 亲密连接 | 清晰 | 否 | 与安全确认、承诺经营轻微重叠 | 保留。 |
| 激情启动 | 需要定义清楚 | 否 | 与主动推进、新鲜探索重叠 | 保留，但不要等同于冲动。 |
| 承诺经营 | 清晰 | 否 | 与现实匹配、关系投入相关 | 保留。 |
| 灵魂理想 | 清晰 | 否 | 与关系叙事、浪漫化相关 | 保留。 |
| 新鲜探索 | 清晰 | 否 | 与自主边界、激情启动重叠 | 保留。 |
| 现实匹配 | 必要新增 | 否 | 与承诺经营相关但不同 | 新增，补足 v1.0 缺口。 |
| 照顾支持 | 清晰但需重定义 | 中 | 与冲突修复、亲密连接重叠 | 保留，重点测支持方式和过度承担。 |
| 表达沟通 | 清晰 | 否 | 与情绪调节相关 | 保留。 |
| 冲突修复 | 清晰 | 否 | 与照顾支持相关 | 保留，题目必须写真实争执/误会。 |
| 情绪调节 | 需要升级 | 中 | 与安全确认、表达沟通重叠 | 从“情绪敏感”升级为“如何处理情绪”。 |
| 关系投入与记忆 | 过宽 | 是 | 与承诺经营、回忆牵引、分离处理重叠 | 建议拆分。 |

### 3.3 重点判断：关系投入与记忆是否过宽

结论：过宽。

它当前承担了至少五类内容：

| 子主题 | 实际测量内容 |
| --- | --- |
| 关系投入 | 愿意付出多少、留下多少、持续经营多少。 |
| 共同经历 | 关系中的共同记忆是否重要。 |
| 投入成本 | 已经投入的时间和情感是否会影响继续留下。 |
| 回忆牵引 | 是否被过去、旧关系、旧细节牵动。 |
| 分离与放下 | 如何面对结束、失去、离开和留恋。 |

如果仍作为一个构念，4 题很难测清楚。用户可能在“愿意投入”上很高，但在“回忆牵引”上很低；也可能很念旧，但并不愿意继续投入一段关系。这两者不应被压成一个分数。

推荐方案：

| 方案 | 构念数 | 题量 | 判断 |
| --- | ---: | ---: | --- |
| 维持 14 构念 | 14 | 56 | 可做 MVP，但第 5 层过薄，需要给“关系投入与记忆”至少 6 题。 |
| 拆成 15 构念 | 15 | 60 | 推荐。结构更清晰，评分更稳定。 |
| 拆成 16 构念 | 16 | 64 | 暂不建议，容易把体系做重。 |

推荐拆分为：

1. 关系投入 / 留下倾向：测用户愿不愿意继续投入、共同建设、在困难中留下。
2. 回忆牵引 / 关系叙事：测用户如何理解共同经历、旧关系、遗憾、留恋和放下。

| 守门人型 | 建议保留 | 自主边界、关系信任、承诺经营 | 可考虑改为“边界守护型” | 否 | 否 | 否 | 需从“难进入”升级为“谨慎信任”。 |

| 收藏家型 | 建议保留但重写 | 回忆牵引、关系叙事、情绪调节 | 暂不改 | 可能与旧船长素材合并 | 否 | 否 | 如果第 5 层拆分，收藏家会更清晰。 |

| 数量 | 判断 |

| 12 个 | 可作为 MVP 延续，但必须重建人格矩阵。 |

## 6. 题量方案比较

| 方案 | 结构 | 优点 | 缺点 | 审计判断 |
| --- | --- | --- | --- | --- |
| A：42 题 | 14 构念 x 3 题 | 比旧 36 完整，用户负担较轻 | 每构念仍偏薄，难放反向/压力题 | 不推荐作为 v2.0 标准方案，可做快速验证版。 |
| B：56 题 | 14 构念 x 4 题 | 覆盖更稳，可安排核心、关系、压力、边界题 | 时长更长，需要更好流程设计 | 可作为 14 构念标准版。 |
| C：56 题 + 判别题 | 基础 56 + 近邻追加 4-8 题 | 能处理接近人格 | 评分复杂，用户体验难控制 | 不建议首版就做，适合 v2.1。 |
| D：60 题 | 15 构念 x 4 题 | 解决第 5 层过宽，结构更干净 | 比 56 多 4 题 | 推荐作为准确性优先方案。 |

推荐：

1. 如果团队接受拆分第 5 层，采用 60 题。
2. 如果必须先控制工作量，采用 56 题，但第 5 层需要特别强化，或在结果解释中降低其权重。
3. 不建议现在为了短流程压回 36 题。
4. 不建议首版做动态追加判别题，先保持评分系统可审计。

## 7. 每构念 4 题结构设计

推荐每个构念 4 题，但用户端不暴露题型。

| 题型 | 作用 | 示例用途 |
| --- | --- | --- |
| 核心倾向题 | 测最直接的内在偏好 | 用户天然更需要靠近、空间、承诺还是变化。 |
| 真实关系场景题 | 测日常关系行为 | 对方晚回消息、计划冲突、情绪不对、关系升温。 |
| 压力/冲突场景题 | 测关系被挑战时的反应 | 误会、冷场、争执、失望、临时变动。 |
| 反向/边界题 | 防止表演式作答 | 用户是否能拒绝、等待、放下、承受不确定。 |

呈现规则：

| 问题 | 建议 |
| --- | --- |
| 是否暴露题型顺序 | 不暴露。设计层知道，用户端不显示。 |
| 是否每构念连续 4 题 | 不建议。连续题会让用户察觉测什么。 |
| 是否打乱题型顺序 | 建议在章节内交错。 |
| 是否章节内交错不同构念 | 建议。每章 2-4 个构念交错，保持叙事推进。 |
| 如何避免表演式作答 | 选项都写成真实策略，不写好人/坏人。 |
| 如何避免题目太直白 | 使用“轻叙事引入 + 真实关系行为”。 |

## 8. 如何避免用户察觉题目在测什么

| 风险 | 对策 |
| --- | --- |
| 题目连续测同一构念 | 章节内交错构念。 |
| 每题都像“核心倾向题” | 混入压力题、边界题、现实场景题。 |
| 选项有明显高低好坏 | 每个选项都是一种真实策略。 |
| 选项双句绑定 | 每个选项只表达一个行为或态度。 |
| 题干过度心理学术语 | 用户端只写生活场景，不写构念名。 |
| 题干过度诗意 | 轻叙事只做入口，选择必须落到真实行为。 |
| 用户想选“理想自我” | 题目多问“你通常会怎么做”，少问“你觉得怎样更好”。 |

推荐题干措辞：

| 不建议 | 建议 |
| --- | --- |
| 你是否缺乏安全感？ | 当对方一整天没有明确回应时，你通常会怎么理解这段沉默？ |
| 你是否愿意成熟沟通？ | 你们刚刚有点不愉快，对方说“算了”。你下一步更可能怎么做？ |
| 你是否重视现实匹配？ | 聊到未来生活节奏时，你发现你们对钱和家庭边界的想法不同。你更在意什么？ |

## 9. 题目写法规则

### 9.1 每题只测一个构念

禁止双重绑定。错误示例：

> 当对方难过时，你会立刻陪着他，并希望他也马上回应你。

这同时测照顾支持、安全确认、亲密连接，不能使用。

### 9.2 选项不能有明显正确答案

错误结构：

| 选项 | 问题 |
| --- | --- |
| A. 我会成熟沟通，尊重对方，也照顾自己。 | 太正确。 |
| D. 我会逃避问题，假装没发生。 | 太负面。 |

应改成真实策略：

| 策略 | 示例 |
| --- | --- |
| 立刻沟通 | 我会趁情绪还在，把我的感受说清楚。 |
| 冷静后再谈 | 我需要先缓一下，等不那么刺痛时再开口。 |
| 等对方先说 | 如果对方愿意解释，我会认真听。 |
| 暂时回避 | 我会先把这件事放下，不想让它继续扩大。 |

### 9.3 避免双句绑定

一个选项不要同时包含两个态度。错误示例：

> 我需要独处，但也希望对方立刻理解并安慰我。

用户可能同意前半句，不同意后半句。

### 9.4 少用纯诗意隐喻，多用真实关系行为

v2.0 仍可保留心岛氛围，但题目必须回到亲密关系行为。题目应让用户能立刻代入自己真实关系中的选择，而不是只在故事里扮演角色。

## 10. 故事线与题目的关系

核心原则：

> 故事线是氛围外壳，题目测的是真实关系行为。故事不能替代真实关系场景，也不能让题目变得模糊。

推荐写法：

> 心岛轻叙事 + 真实关系场景。

不建议：

> 月光照在湖面，你看见另一个自己。

也不建议：

> 当你明显感觉对方情绪不对，但对方说没事，你通常会怎么做？

更合适：

> 在月潮湖边，你想起一次相似的时刻：对方明明情绪不对，却只说“没事”。那时你通常会怎么做？

这样既保留心岛场景，也测真实关系行为。

## 11. 题目模板示例

### 11.1 叙事引入 + 真实回忆型

模板：

> 在【心岛地点】停下时，你想起一段真实关系里的相似时刻：【现实关系情境】。那时你更可能怎么做？

示例 1：

> 在回声港湾，你听见很久才传回来的声音。你想起一次对方一整天没有明确回应的时刻。那时你更可能怎么理解这段沉默？

示例 2：

> 在裂隙火山旁，你看到岩缝慢慢冷却。你想起一次争执后两个人都没有立刻开口的时刻。那时你更可能怎么做？

### 11.2 当前航行场景 + 关系投射型

模板：

> 航行中出现【轻叙事事件】，它让你想到关系里的【单一构念场景】。你会更接近哪种选择？

示例 1：

> 船在两条航线前停下：一条更靠近人群，一条更安静自由。它让你想到关系变得很密集时的自己。你会更接近哪种选择？

示例 2：

> 航海图上出现一片未知海域。它让你想到一段关系进入新阶段时的选择。你更可能怎么面对未知？

### 11.3 现实恋爱场景 + 心岛轻隐喻型

模板：

> 【现实关系场景】。如果把这件事放在心岛上，它像【轻隐喻】。你通常会怎么回应？

示例 1：

> 对方说想见你，但你这周已经很累。如果把这件事放在心岛上，它像一座桥突然靠得很近。你通常会怎么回应？

示例 2：

> 你们聊到未来住在哪、钱怎么安排、要不要见家人。如果把这件事放在心岛上，它像一张需要一起看的航海图。你最先会看哪里？

## 12. 五章节做题流程

### 12.1 原结构评估

| 章节 | 当前构念 | 题数 | 判断 |
| --- | --- | ---: | --- |
| 第 1 章：靠近与防线 | 安全确认、自主边界、关系信任 | 12 | 合理。 |
| 第 2 章：心动与靠近 | 亲密连接、激情启动、承诺经营 | 12 | 合理。 |
| 第 3 章：爱人的方式 | 灵魂理想、新鲜探索、现实匹配、照顾支持 | 16 | 合理，但内容最多，需要节奏控制。 |
| 第 4 章：关系出现裂痕时 | 表达沟通、冲突修复、情绪调节 | 12 | 合理。 |
| 第 5 章：留下、离开与记住 | 关系投入与记忆 | 4 | 太薄。 |

第 5 章过薄。它既承担结尾情绪，也承担关系投入、回忆、分离、放下等复杂内容。只用 4 题会让结果解释不稳定。

### 12.2 推荐章节结构 A：14 构念 56 题

| 章节 | 白话标题 | 对应构念 | 题数 |
| --- | --- | --- | ---: |
| 第 1 章 | 靠近时，你怎样安心 | 安全确认、自主边界、关系信任 | 12 |
| 第 2 章 | 心动后，你怎样靠近 | 亲密连接、激情启动、承诺经营 | 12 |
| 第 3 章 | 你用什么方式爱人 | 灵魂理想、新鲜探索、现实匹配、照顾支持 | 16 |
| 第 4 章 | 关系有裂痕时，你怎样处理 | 表达沟通、冲突修复、情绪调节 | 12 |
| 第 5 章 | 留下、离开，以及记住 | 关系投入与记忆 | 4 |

如果使用该结构，建议第 5 章不要只有 4 题，而是在第 2 章和第 5 章之间分摊“关系投入”题，避免最后一章太薄。

### 12.3 推荐章节结构 B：15 构念 60 题

| 章节 | 白话标题 | 对应构念 | 题数 |
| --- | --- | --- | ---: |
| 第 1 章 | 靠近时，你怎样安心 | 安全确认、自主边界、关系信任 | 12 |
| 第 2 章 | 心动后，你怎样靠近 | 亲密连接、激情启动、承诺经营 | 12 |
| 第 3 章 | 你用什么方式爱人 | 灵魂理想、新鲜探索、现实匹配、照顾支持 | 16 |
| 第 4 章 | 关系有裂痕时，你怎样处理 | 表达沟通、冲突修复、情绪调节 | 12 |
| 第 5 章 | 留下、离开，以及记住 | 关系投入/留下倾向、回忆牵引/关系叙事 | 8 |

推荐采用结构 B。它只比 56 题多 4 题，但能明显改善第 5 层结构。

## 13. 第 5 章是否过薄的判断

结论：如果维持 14 构念，第 5 章过薄；如果拆成 15 构念并给 8 题，第 5 章合理。

第 5 章的价值不只是“结尾情绪”，它关系到用户如何理解：

| 内容 | 是否应被测 |
| --- | --- |
| 愿不愿意继续投入 | 是 |
| 是否容易因为投入成本留下 | 是 |
| 是否被共同经历牵动 | 是 |
| 是否能带着记忆离开 | 是 |
| 是否把回忆当作爱的证明 | 是 |

建议：

1. 第 5 章保留，但改为 8 题。
2. 章节名保持轻叙事，但题目写真实关系场景。
3. 不要把第 5 章并入承诺经营，否则“留下”与“长期建设”会混淆。
4. 不要把第 5 章并入现实匹配，否则“现实可行性”和“情感留痕”会混淆。

## 14. v2.0 新故事线方案

### 14.1 故事总标题

建议标题：

> 从近岸到心岛：一段关系里的内心航行

它比“从近岸到心岛”更明确地告诉用户：这不是冒险游戏，而是关系中的内心航行。

### 14.2 开场设定

建议文案方向：

> 你将沿着一条通往心岛的航线，经过五段关系中的内心海域。每一段航行都不是任务，而是一面镜子：它会让你想起自己在亲密关系里如何安心、靠近、心动、表达、修复、留下或放下。

### 14.3 五章标题与引导语

| 章节 | 标题 | 引导语 | 对应构念 | 题目风格 | 避免误义 |
| --- | --- | --- | --- | --- | --- |
| 1 | 靠近时，你怎样安心 | 当一段关系开始靠近，你会先寻找确定，还是先保留自己的位置？ | 安全确认、自主边界、关系信任 | 关系早期、回应、距离、信任 | 不要让“靠近的人”像陌生人。 |
| 2 | 心动后，你怎样靠近 | 心动不只是一瞬间，也包括你是否愿意让它进入生活。 | 亲密连接、激情启动、承诺经营 | 心动、主动、日常靠近、长期意愿 | 不要把承诺写成婚姻压力。 |
| 3 | 你用什么方式爱人 | 有人被灵魂打动，有人被新鲜点亮，有人会先看生活是否真的合拍。 | 灵魂理想、新鲜探索、现实匹配、照顾支持 | 被什么吸引、如何选择、如何支持 | 不要把现实匹配写成势利。 |
| 4 | 关系有裂痕时，你怎样处理 | 亲密关系不会一直顺风，重要的是风浪来时你如何回应。 | 表达沟通、冲突修复、情绪调节 | 误会、争执、情绪、道歉、修复 | 不要把“修复”写成单方面忍让。 |
| 5 | 留下、离开，以及记住 | 有些关系会继续，有些关系会成为记忆。你如何理解它们留下的重量？ | 关系投入/留下倾向、回忆牵引/关系叙事 | 投入、共同经历、留恋、放下 | 不要把念旧等同于放不下。 |

### 14.4 结尾过渡文案

建议方向：

> 航线已经抵达心岛深处。刚才的每一次选择，都不是为了给你贴上复杂标签，而是为了看见你在亲密关系里最自然的靠近方式。接下来，心岛会把这些选择整理成一个主性人格和一份更白话的情感解析。

### 14.5 故事线是否建议保留

建议保留，但改成轻叙事测试，不保留强剧情。

| 叙事强度 | 判断 |
| --- | --- |
| 强剧情/RPG | 不建议，会牺牲题目准确性。 |
| 完全普通问卷 | 不建议，会失去心岛差异化。 |
| 轻叙事 + 真实关系行为 | 推荐。 |

## 15. 做题体验优化方案

56-60 题会变长，不能靠压缩构念牺牲准确性，应靠流程降低疲劳。

| 体验项 | 建议 |
| --- | --- |
| 每章完成提示 | 保留，使用一句短提示，不做长剧情。 |
| 每章题数展示 | 显示“本章 12 题”或“本章 8 题”，降低未知焦虑。 |
| 总进度 | 显示总进度条和题号，如 `18 / 60`。 |
| 是否显示剩余时间 | 可显示“约 7-9 分钟”，不建议每题倒计时。 |
| 是否中途保存 | 建议保留 localStorage 自动保存，长题量更需要。 |
| 是否允许上一题 | 建议允许，且保持次级视觉。 |
| 章节间过渡 | 建议保留短过渡，但不超过 2 秒或可跳过。 |
| 题目长度 | 题干尽量 1-2 行，最多 70-90 字。 |
| 选项长度 | 每个选项尽量 18-34 字，避免双句。 |
| 动画节奏 | 轻微淡入即可，不做复杂动画。 |
| 移动端首屏 | 每题首屏至少看到题干和 2 个选项。 |
| 完成激励 | 每章结束给“已完成 2/5 航段”式进度反馈。 |

## 16. 最终结果页展示结构

用户端只展示一个主性人格。复杂评分信息进入白话解析，不作为标签展示。

推荐结构：

1. 主性人格 Hero。
2. 拟人图。
3. 一句命中句。
4. 3 个关键词。
5. 个人情感底色。
6. 你在关系里最容易卡住的地方。
7. 你适合的相处方式。
8. 生成分享卡。
9. 展开更多细节。

禁止用户端展示：

| 禁止项 | 原因 |
| --- | --- |
| 副导 | 概念过重，用户不需要。 |
| 副岛 | 会削弱主结果记忆点。 |
| 副人格 | 让用户分心，传播不清晰。 |
| 张力潮汐 | 术语化。 |
| 构念雷达 | 太复杂，且容易被当成专业诊断。 |
| Top2 | 会让用户怀疑主结果。 |
| 14/15 构念得分表 | 内部有用，用户端过重。 |

内部可使用：

| 内部信息 | 用户端表达方式 |
| --- | --- |
| 第二匹配人格 | 融入白话解释，不说“你的副人格是”。 |
| 高分构念 | 写成“你更容易……” |
| 低分构念 | 写成“你不太习惯……” |
| 构念冲突 | 写成“你一方面……另一方面……” |
| 近邻人格 | 用于文案判别，不展示标签。 |

## 17. 后续执行路线

### 阶段 1：框架定稿

确认：

1. 五层结构是否最终保留。
2. 构念数采用 14、15 还是其他。
3. 最终题量采用 56、60 还是 56+判别题。
4. 主性人格数量范围。

### 阶段 2：题库候选生成

生成：

1. 每构念 4 道候选题。
2. 每题标注构念、题型、场景、选项策略。
3. 如果构念过宽，增加候选题而不是压缩。
4. 每题只绑定一个构念。

### 阶段 3：题库审计

检查：

1. 是否单构念。
2. 是否双句绑定。
3. 是否有明显正确答案。
4. 是否故事过强。
5. 是否现实场景不足。
6. 是否缺少用户想选的真实策略。

### 阶段 4：人格矩阵重建

基于新构念重新设计：

1. 保留人格。
2. 合并人格。
3. 改名人格。
4. 新增人格。
5. 每个人格的构念锚点。
6. 每个人格的反向边界。

### 阶段 5：评分系统重构

根据新构念和新题库设计：

1. 构念分。
2. 主人格匹配。
3. 内部第二倾向。
4. 近邻人格判别。
5. 白话解析生成规则。

### 阶段 6：结果页文案重写

重写：

1. 命中句。
2. 关键词。
3. 情感底色。
4. 关系卡点。
5. 相处建议。
6. 分享卡短句。

### 阶段 7：代码实现

最后才进入 Codex 代码实现。不要在框架未定稿前修改 `app.js`、题库、评分或结果页。
