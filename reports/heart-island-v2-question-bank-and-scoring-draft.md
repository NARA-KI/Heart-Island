# 心岛 v2.0 60 题候选题库与评分机制草案

## 1. 总结结论

本轮生成 v2.0 的 60 题候选题库草案与评分机制草案。报告只作为后续人工审题、题库审计、评分实现前的数据设计参考，不写入生产题库，不改动现有评分系统。

核心结论：

| 项目 | 结论 |
| --- | --- |
| 题库结构 | 采用 15 构念 x 每构念 4 题 = 60 题。 |
| 章节结构 | 采用 5 章：靠近安心、心动靠近、爱人方式、裂痕处理、留下记住。 |
| 单题原则 | 每题只绑定一个主构念。 |
| 选项结构 | 每题 4 个选项，内部使用 0 / 33 / 67 / 100。 |
| 反向题 | 每个构念设置 1 道反向或边界题，并明确 `isReverse: true`。 |
| 评分机制 | 先聚合 15 构念分，再与 15 主性人格 targetVector 匹配。 |
| 用户端展示 | 只展示一个主性人格；构念分、Top2、置信度只用于白话解析。 |
| 当前状态 | 本报告是草案，必须进入人工审题与模拟分布验证后才能实现。 |

## 6. 60 题候选题库

说明：以下题目为候选草案。题干采用“轻叙事 + 真实关系行为”，选项都应被理解为真实策略，不代表好坏。分值为该选项对当前主构念的最终计分。

### v2-q01

- 章节：第 1 章 靠近时，你怎样安心
- 构念：安全确认
- 构念代码：SC
- 题型：核心倾向
- 是否反向题：false
- 题干：在近岸灯标旁，你想起一段刚开始靠近的关系。对方没有明确说过你们现在算什么，你通常更在意什么？
- 选项：
  - A. 我会先观察相处，不急着要一个说法。
  - B. 我希望至少知道对方是不是认真靠近。
  - C. 我会直接问清楚，不想长期猜。
  - D. 我更看行动，暂时不需要语言确认。
- 分值：
  - A: 33
  - B: 67
  - C: 100
  - D: 0
- 评分说明：高分代表更需要明确回应和关系信号；低分代表能承受较多模糊。
- 区分人格：港湾型、镜像型、守门人、岛屿型。
- 风险说明：避免把需要确认写成“缺爱”，后续可检查 C 是否过于直白。

## 7. 构念聚合规则

每个构念 4 题，计算平均分：

```text
constructScore = average(questionScoresForConstruct)
```

建议同时记录：

| 字段 | 说明 |
| --- | --- |
| `mean` | 构念平均分，进入人格匹配。 |
| `stdDev` | 4 题离散度，用于判断置信度。 |
| `reverseConsistency` | 反向题与其他题的方向一致性。 |
| `confidence` | high / medium / low，只用于解析语气。 |

构念置信度建议：

| 情况 | 置信度 | 解析语气 |
| --- | --- | --- |
| 4 题方向一致，离散度低 | high | 可以使用较确定的白话描述。 |
| 分数中等分散 | medium | 使用“你可能”“有时”。 |
| 核心题与反向题明显冲突 | low | 不强解释，只作为辅助素材。 |

## 8. 反向题处理规则

反向题必须显式标记 `isReverse: true`。反向题的作用不是把答案“倒扣”，而是通过反向场景验证构念方向。

实现时建议不要根据题号或选项顺序推断分值，只读取每个 optionId 对应的 score。

示例：

```json
{
  "qid": "v2-q08",
  "constructCode": "AU",
  "isReverse": true,
  "scoreMap": {
    "A": 0,
    "B": 67,
    "C": 100,
    "D": 33
  }
}
```

## 9. 人格匹配规则

建议采用四步：

1. 计算用户 15 构念分。
2. 与 15 主性人格 targetVector 做基础距离匹配。
3. 对每个人格的 3 个核心构念加权。
4. 对排斥构念或边界构念做扣分，并记录 Top1 / Top2 gap。

用户端只展示 Top1 主性人格。Top2、gap、低置信构念只用于白话解析，不作为标签展示。

## 10. 白话解析素材提取规则

内部可提取：

| 素材 | 用途 |
| --- | --- |
| 主人格 | 决定 Hero、命中句、关键词。 |
| 高分构念 | 写“你更容易……” |
| 低分构念 | 写“你不太习惯……” |
| 构念组合 | 写“一方面……另一方面……” |
| 低置信构念 | 降低语气强度，避免绝对判断。 |
| 题目辅助标签 | 生成更具体的关系卡点和相处建议。 |

用户端不展示：

| 不展示项 | 原因 |
| --- | --- |
| 15 构念得分表 | 信息过重，像专业量表。 |
| Top2 / 副人格 | 会削弱主结果记忆点。 |
| 构念雷达图 | 容易被误解为心理诊断。 |
| 置信度术语 | 用户不需要看到内部评分质量词。 |

## 12. 发现的问题

1. 60 题草案已经覆盖 15 构念，但部分相邻构念天然会重叠，例如安全确认与关系信任、亲密连接与照顾支持、冲突修复与表达沟通。
2. 关系投入与回忆牵引最容易互相污染，需要人工审题确保“留下”和“记住”分开。
3. 照顾支持题容易把高分写成道德更好，后续需要继续降低好坏感。
4. 情绪调节题容易滑向心理诊断语气，正式文案中必须保持恋爱人格测试边界。
5. 当前题库还没有做真实用户作答模拟，不能直接进入代码。
