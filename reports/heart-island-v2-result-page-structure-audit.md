# 心岛 v2.0 结果页结构审计报告

## 1. 旧版结果页结构

基于当前根目录 `app.js`、`styles.css`、`index.html`、`release/heart-island-beta-0.9.9.4-rc` 和历史 reports 检查，旧版结果页主要由以下模块组成：

1. `#result-screen` / `#result-card` 作为结果页容器。
2. `result-hero` 登岛档案 Hero：包含“登岛档案”、核心主岛、人格式名称、subtitle、匹配度、关键词、命中句、置信度、分享卡入口、拟人图。
3. 人格说明书 `persona-manual`：解释“你在关系里的样子”“真正需要的爱”“为什么你会是某人格”。
4. 关系惯性模块：优势、容易卡住的地方、适合关系节奏。
5. 给你的关系建议：靠近时、不安时、冲突时。
6. 展开更多细节：12 维心岛地图、Top5、相近人格、完整解读、关系标签、旅途回顾、人格图鉴入口。
7. 分享与反馈：生成分享卡、生成长图、保存、分享、复制分享文字、结果保存、反馈。

旧版还接入了 12 张人格拟人图和结果背景图，分享卡逻辑只围绕主人格身份传播。

## 2. 旧版精华

建议保留：

- “登岛档案”世界观标签，它能把测试结果从普通问卷结果变成心岛身份确认。
- 拟人图作为 Hero 视觉中心，旧版代码已有 WebP + SVG fallback 的思路。
- 人格名、命中句、关键词在首屏内完成身份确认。
- “人格说明书”的解释口吻，适合回答用户“为什么我是这个结果”。
- 优势 / 盲点 / 关系需要 / 适合关系环境，比纯排行榜更能帮助用户判断贴合度。
- 分享卡入口靠前，但不抢掉结果阅读。
- 折叠更多细节的做法：把调试型或重信息内容下移。

## 3. 旧版问题

建议优化或删除：

- Top5、匹配度、分数、gap、置信度等算法信息容易让用户把结果页当成调试报告。
- “关系回声：XX型”“与 XX 很近”会削弱主人格认领感。
- 12 维地图、Top5、旅途回顾、图鉴、分享、反馈同时出现，移动端层级容易过重。
- 多个折叠区会让用户不知道核心答案在哪里。
- 结果页顶部出现匹配度和置信度时，用户会先评估算法，而不是理解自己。
- 旧版曾多次报告“信息过碎、模块太多、标题太散”，Beta 0.9.8.2 已经明确做过减法。

## 4. 市场同类产品结构启发

本轮只参考信息架构，不复制品牌视觉、名称、文案、插画或具体布局。

成熟人格测试结果页通常采用以下阅读顺序：

1. 先给唯一身份：人格名、短句、关键词。
2. 再给结果快照：用户快速知道这个类型的核心倾向。
3. 用具体行为场景证明结果：如何靠近、表达、投入、处理冲突。
4. 展示优势和盲点：让用户产生共鸣，同时避免只夸不解释。
5. 解释核心维度：把抽象分数转成自然语言。
6. 给成长建议或关系提醒：让用户带走可执行价值。
7. 最后提供分享 / 保存。
8. 复杂信息渐进展开，而不是首屏塞满。

对心岛 v2 的启发：普通用户结果页不应该展示算法排序，而应先建立“这就是我的心岛人格”的体验；内部排名、gap、Top5 适合放在研究视图。

## 5. 心岛 v2 推荐结构

普通用户结果页建议采用：

1. 登岛结果 Hero：拟人图、你的心岛人格、唯一主人格、命中句、3-5 个关键词。
2. 你的关系底色：用构念分数生成个性化关系画像。
3. 你是怎样爱人的：如何靠近、如何表达、如何投入、如何面对承诺、如何处理冲突、如何看待空间。
4. 你的天赋：3-5 个具体优势。
5. 你的关系惯性：2-4 个盲点或自动反应，避免诊断和贬低。
6. 为什么你会得到这个结果：突出倾向 + 较弱倾向 + 它们如何共同形成主人格。
7. 你真正需要的关系：核心需要、合适环境、容易消耗的关系模式。
8. 给你的关系提醒：2-3 条具体建议。
9. 分享卡：人格图、人格名、命中句、3 个关键词、心岛品牌。

## 6. 内容优先级

首屏必须完成：

- 只显示一个主人格。
- 显示人格图或至少人格身份区。
- 显示命中句与关键词。
- 不显示 Top2、Top3、gap、lowConfidence、距离、相似度。

中段必须完成：

- 用关系行为证明结果，不写成百科条目。
- 解释构念时不显示 SC/AU/TR 等英文代码。
- 明确低 CL 等较弱倾向不等于没有感情。

后段必须完成：

- 给出关系需要、适合环境和具体提醒。
- 分享入口保持轻量。

## 7. 移动端阅读顺序

移动端应保持单列：

1. Hero 身份确认。
2. 关系底色。
3. 行为场景。
4. 优势 / 盲点。
5. 为什么得到这个结果。
6. 关系需要和提醒。
7. 反馈和导出。

核心解析不能全部折叠；研究型信息不得出现在普通页。

## 8. 最终实施范围

本轮实施只修改：

- `tools/v2-pilot` 普通内测工具。
- `pilot-deploy/v2` 部署镜像。
- `result-explanation.mjs` 结果解释模块。
- 必要的 pilot-only persona description 数据。
- 必要的分析脚本兼容字段。
- 本轮报告。

不修改：

- 正式生产 `app.js`、`index.html`、`styles.css`。
- `core/scoring.mjs`。
- `core/calibration-profiles.mjs`。
- 60 题题库文字。
- 选项分值。
- baseline / candidate-A targetVector。
- 距离算法。
- 低置信规则。

## 9. 结论

实施方向不是简单删除 Top2 / Top3，而是把普通结果页从“算法调试报告”改成“单人格登岛档案”。后台继续保留 Top5、gap、lowConfidence、baseline / candidate-A，review 页面继续服务人格边界和评分校准。
