# Codex 项目规则同步报告

## 1. 本轮目标

本轮目标是整理一份长期使用的项目规则文档，用来同步用户与 Codex 在多轮沟通中已经确认的协作约定、开发流程、项目锚点、禁止事项和后续执行规范。

本轮不是功能开发，不是 UI 修改，不是题库修改，不是评分修改，也不是代码重构。

## 2. 新增/更新的规则文档路径

新增长期规则文档：

```text
docs/CODEX_PROJECT_RULES_AND_WORKFLOW.md
```

新增本轮同步报告：

```text
reports/codex-project-rules-sync-report.md
```

## 3. 规则文档包含的模块

规则文档已包含以下模块：

1. 文档定位与使用目的。
2. 总协作原则。
3. Codex 执行流程规则。
4. 心岛项目长期规则。
5. 心岛 v1.0 旧锚点。
6. 心岛 v2.0 新锚点。
7. 心岛 v2.0 15 构念与 60 题方向。
8. 心岛 v2.0 题库、评分、人格、结果展示、轻叙事规则。
9. 小红书项目规则。
10. Research / Strategy / Development 阶段规则。
11. 版本与报告规则。
12. Codex 禁止事项总表。
13. Codex 每次任务前自检清单。

## 7. 是否改动 UI

没有。

本轮没有修改任何页面结构、样式、图片、交互或移动端布局。

## 8. 后续 Codex 如何使用该文档

后续 Codex 每次执行项目任务前，应优先阅读：

```text
docs/CODEX_PROJECT_RULES_AND_WORKFLOW.md
```

并结合当前任务指定的最新锚点报告，判断：

1. 当前属于哪个项目。
2. 当前属于 Research、Strategy 还是 Development。
3. 用户是否允许改代码。
4. 是否只应输出报告。
5. 是否涉及题库、评分、人格、UI 或部署。
6. 是否符合心岛 v2.0 新锚点。
7. 是否符合小红书项目的半自动、内容质量优先方向。
8. 是否触犯禁止事项。

## 9. 下一步建议

下一步如果继续心岛项目，应按当前已确认顺序推进：

```text
构念定稿
-> 主性人格矩阵确认
-> 题库与评分架构确认
-> 60 题候选题库生成
-> 题库审计
-> 评分系统落地
-> 结果文案重写
-> UI / 代码实现
-> 测试与部署
```

不要跳过结构阶段直接改代码。
