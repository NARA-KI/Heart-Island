# 心岛 v2.0 题库典型人格模拟作答设计表

## 1. 本轮结论摘要

本轮版本目标：`v2.0-question-bank-persona-simulation-plan`。

本轮只做典型人格模拟作答设计，不改代码，不接入正式题库，不修改评分机制，不修改人格类型体系，不修改核心结果算法。

本报告基于以下现有 reports：

| 输入依据 | 用途 |
| --- | --- |
| `reports/heart-island-v2-question-bank-audit-pass-2-human-review.md` | 读取第二轮重点题审题结论和风险题。 |
| `reports/heart-island-v2-question-bank-and-scoring-draft.md` | 读取 15 构念、60 题题号分布、15 主性人格锚点。 |
| `reports/heart-island-v2-personality-questionnaire-scoring-architecture.md` | 读取 15 构念定义、人格高/中/低构念、targetVector 草案。 |
| `reports/heart-island-v2-personality-naming-system-rebuild-plan.md` | 辅助确认部分新增/改名人格与当前展示名的关系。 |

本轮结论：

1. 可以进入典型人格模拟执行。
2. 暂不建议进入结构化题库草案。
3. 不建议进入代码实现。
4. 典型人格模拟应优先验证 15 个主性人格是否各自能命中，以及 6 组易混人格能否拉开。

## 7. 模拟作答执行方案

### 7.1 模拟组设计

| 模拟组 | 数量 | 目的 |
| --- | ---: | --- |
| 15 个主性人格理想路径 | 15 组 | 验证每个主性人格是否能在理想路径下命中自己。 |
| 6 组易混人格对照 | 至少 18 组 | 验证相邻人格边界是否能拉开。 |
| 轻微随机扰动路径 | 每人格 2-3 组 | 验证结果是否对单题波动过度敏感。 |
| 风险题压力路径 | 14 题专项 | 验证 q06/q11/q15/q21/q28/q32/q36/q38/q41/q47/q50/q57/q58/q60 的影响。 |

建议最小模拟规模：

```text
15 个主性人格理想路径
+ 18 个易混人格对照路径
+ 30-45 个轻微扰动路径
= 63-78 组模拟
```

### 7.2 每组输出字段

每组模拟建议输出：

| 输出项 | 说明 |
| --- | --- |
| personaScenarioId | 例如 `ideal-lighthouse-01`、`confusable-gatekeeper-islander-01`。 |
| 预期主人格 | 模拟设计希望命中的主人格。 |
| 60 题选项序列 | A/B/C/D。 |
| 15 构念分 | SC、AU、TR、CL、PA、CM、SI、NV、RM、CS、EC、CR、ER、RI、MN。 |
| Top5 人格 | 主人格和近邻人格。 |
| Top1-Top2 gap | 判断边界是否足够清楚。 |
| 命中状态 | 命中 / 相邻人格误判 / 非相邻误判。 |
| 风险题贡献 | 标记 q06/q11/q15/q21/q28/q32/q36/q38/q41/q47/q50/q57/q58/q60 对排序的影响。 |

### 7.3 随机扰动规则

建议每个理想路径追加 2-3 组扰动：

1. 高分构念中，随机把 1-2 道 100 改为 67。
2. 中分构念中，随机把 1 道 67 改为 33 或 100。
3. 低分构念中，随机把 1 道 0 改为 33。
4. 不允许一次扰动跨越太多题，避免模拟变成另一个人格。
5. 风险题必须单独标记，便于观察单题对主结果的影响。

### 7.4 通过 / 失败判断

| 检查项 | 通过标准 | 失败信号 |
| --- | --- | --- |
| 15 主性人格理想路径 | 15/15 命中，或至少 14/15 命中且唯一失败为可解释相邻人格 | 多个主性人格被同一个类型吸走 |
| 易混人格对照 | 每组内人格可按关键构念拉开，Top1 符合预期 | 三者反复互换，gap 过小 |
| 随机扰动 | 轻微扰动后主结果保持稳定或落到合理相邻人格 | 单题变化导致非相邻人格跳出 |
| 风险题压力 | 风险题不会让某一人格系统性过高频 | q11 抬高岛屿/候鸟，q28/q32/q36 抬高灯塔，q41/q50 抬高摆渡人 |
| 分布健康 | 没有类型在模拟集中明显垄断 Top1 | 某一类型在非自身路径中频繁 Top1 |

## 8. 是否建议进入结构化题库草案

暂不建议。

理由：

1. 本轮只是模拟作答设计，还没有执行模拟。
2. 用户已拍板 8 道关键题，但仍需要用模拟验证它们是否影响人格分布。
3. 15 个主性人格的 targetVector 草案仍停留在 reports 文档中，尚未做真实路径压力测试。
4. 在模拟结果出来前，过早生成结构化题库草案会把未验证的题目和人格边界固化。

可以进入结构化题库草案的前置条件：

1. 15 个主性人格理想路径基本命中。
2. 6 组易混人格对照能够解释性拉开。
3. q06、q11、q15、q21、q28、q32、q36、q38、q41、q47、q50、q57、q58、q60 没有造成单一人格过度高频。
4. 用户确认当前 15 展示名是否沿用，尤其是探险家 / 同行者 / 港湾型 / 摆渡人与架构文档命名的对应关系。
