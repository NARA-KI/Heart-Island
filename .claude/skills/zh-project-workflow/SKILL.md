# 中文项目工作流程

## 语言规则

1. 用户可见说明、报告和总结默认使用中文。
2. 代码标识符、API 字段、路径、命令和提交信息按项目规范保留英文。
3. 技术术语优先使用通用中文翻译，必要时括号标注英文原文。

## 开始工作前必读

1. 读取 `CLAUDE.md`（如存在）。
2. 读取项目记忆或 CONTEXT 文档（如存在）。
3. 检查 `git status`、当前分支和 HEAD。
4. 理解当前工作目录结构和关键文件。

## 工作分类

先区分问题类型：
- **观察**：仅阅读和分析，不修改代码。
- **建议**：输出方案和影响范围，等待确认后再执行。
- **已确认决策**：用户已明确授权，可直接执行。

## 产品锚点原则

1. 已冻结的产品锚点不得自行推翻（如评分机制、人格映射、题库结构）。
2. 未明确要求发散时，不重新规划整个产品。
3. 先声明允许修改范围和禁止修改范围。

## 修改规范

1. 高风险改动先建立可复现测试或失败信号。
2. 小修、文案和 CSS 保持最小修改。
3. 多文件重构必须先输出方案和影响范围。
4. 不要为了视觉效果牺牲测试可读性。
5. 小步修改，不要一次性重构太多。

## 测试要求

1. 完成后运行相关测试并报告真实结果。
2. 检查桌面端 1440px 和移动端 390px 效果。
3. 检查做题流程和结果页是否完整。
4. 不将"代码回归通过"表述为"真人体验一定通过"。

## 禁止事项

未经明确授权不得：
- commit
- push
- merge
- deploy
- 修改云函数、环境变量、网关和生产配置
- 删除现有素材文件
- 随意重命名 assets 路径
- 大规模重写核心文件

其他禁止：
- 不将 AI 模拟用户冒充真实测试者。
- 密钥、Token、Cookie、环境变量必须脱敏。
- 不为了埋点重构应用。
- 不修改评分和人格逻辑。

## 长任务交接

长任务结束时使用 handoff 保存：
- 当前目标
- 已完成事项
- 决策锚点
- 当前分支与 commit
- 未解决问题
- 下一步最小动作

## 最终汇报格式

必须包括：
- 修改文件清单
- 未修改的重要区域
- 测试结果
- git 状态
- 是否提交
- 是否部署
- 剩余风险
