# Domain Docs

Single-context repo. Skills should read these when exploring the codebase:

- **`CLAUDE.md`** at repo root — project rules and context
- **`docs/adr/`** — not yet created; skills that produce architectural decisions should populate this directory
- **`reports/`** — historical reports documenting past decisions and fixes

If files don't exist, proceed silently. The domain-modeling skill creates ADRs lazily when terms or decisions actually get resolved.

## Use consistent vocabulary

When output names a domain concept, use terms as defined in CLAUDE.md and project documentation.
